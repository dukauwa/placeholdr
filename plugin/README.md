# dreamlog

A Claude Code plugin. You capture fragments — notes, overheards, half-thoughts. Each morning, before you sit down, Dreamlog reads what you've gathered and writes one small literary dream per cluster: a hypothesis, a question, or a weird connection. The letter is on the desk when you open Claude Code with your coffee.

Everything lives locally. No API keys, no cloud database. Dreams are written by the same Claude already running your Claude Code session.

## Install

```bash
claude plugin install https://github.com/dukauwa/placeholdr/tree/main/plugin
```

Requires Node 18.17+ and a C toolchain for `better-sqlite3` (installed automatically on most systems).

## Quickstart

1. `/dreamlog:demo` — load 41 sample memories and 3 pre-baked dreams.
2. `/dreamlog:read` — see what the ritual feels like.
3. `/dreamlog:remember "I have been thinking about..."` — start your own log.
4. Sleep. Next morning, SessionStart will nudge: `/dreamlog:dream`.
5. `/dreamlog:read` — your morning letter.

## Commands

| Command | What it does |
| --- | --- |
| `/dreamlog:remember <text>` | Capture a fragment. Chunks to ~300 tokens and inserts into the local memory store. |
| `/dreamlog:remember-file <path>` | Ingest an existing text file (`.txt`, `.md`, journal exports) as memories. |
| `/dreamlog:dream` | Sample memories, cluster them, and write today's dreams in the Dreamlog voice. Default 5 per run. |
| `/dreamlog:read` | Today's dreams, in the editorial reading layout. |
| `/dreamlog:log [N]` | The last N dreams (default 20), oldest last. |
| `/dreamlog:demo` | Load sample content so first-run has something to show. |
| `/dreamlog:status` | Memory count, dream count, last dream time, budget. |
| `/dreamlog:schedule` | Install a 9am daily scheduler (macOS launchd / Linux systemd). See [Windows](docs/windows-scheduling.md) for the manual recipe. |
| `/dreamlog:unschedule` | Remove the 9am scheduler. |

## Scheduling

By default, `/dreamlog:dream` runs when you explicitly invoke it or when the SessionStart hook nudges you on the first session of the day. If you want the dream to be *already waiting* before you open Claude Code, run `/dreamlog:schedule` once. It installs a platform-appropriate timer that fires headless `claude -p "/dreamlog:dream"` at 9am, using your existing Claude Code auth.

- **macOS**: writes `~/Library/LaunchAgents/dev.dreamlog.daily.plist` and loads it with `launchctl`. Logs to `~/.dreamlog/schedule.log`.
- **Linux**: writes `~/.config/systemd/user/dreamlog.{service,timer}` with `Persistent=true` (so it catches up if your machine was asleep at 9am).
- **Windows**: manual setup via Task Scheduler — see [docs/windows-scheduling.md](docs/windows-scheduling.md).

If your machine is asleep at 9am, both macOS and Linux catch up when it wakes; you'll find the dream waiting when you open the laptop.

## Privacy

- Everything is stored locally in `~/.dreamlog/dreamlog.db` (SQLite, WAL mode).
- The MCP server the plugin ships (`bin/dreamlog-mcp.mjs`) makes zero network calls. You can verify: `lsof -p $(pgrep -f dreamlog-mcp)` shows no sockets.
- Dreams are generated by the Claude in your Claude Code session. That session's usage is governed by your existing Claude Code account — no extra API keys, no third-party calls.
- There is no telemetry, no analytics, no "phone home."

## Uninstall

```bash
# Remove the plugin
/plugin remove dreamlog

# Remove your data (destructive — deletes all memories and dreams)
rm -rf ~/.dreamlog

# Remove the scheduler if you installed it
/dreamlog:unschedule   # run this BEFORE uninstalling for cleanup
```

## Tuning

- `/dreamlog:status` shows your current dream budget (default 5/day).
- To change it: nothing in the UI yet — for now, open `~/.dreamlog/dreamlog.db` and `INSERT INTO meta (key, value) VALUES ('dream_budget', '8');` or equivalent. The next `/dreamlog:dream` will read the new value.
- The retrieval band (which neighbors count as "related but surprising") is tuned via constants at the top of `bin/dreamlog-mcp.mjs`: `skip_top=4`, `per_cluster=3`. Adjust and restart the plugin (`/reload-plugins`).

## Sibling — the web app

This plugin shares lineage with a Next.js web reading view (same repo, parent directory). If you want the full editorial "morning letter" visual treatment in a browser, that's the form factor for it. The plugin is the write path + CLI reading path; the web app is the polished read path. They don't share a database — the web app uses MongoDB Atlas, the plugin uses local SQLite.
